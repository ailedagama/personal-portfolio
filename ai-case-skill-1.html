SKILL DESIGN / 任务流程与质量约束

企业招标技术规范书 AI 编写助手

将客户调研、功能清单、逐章确认与规范校验组织成可复用 Skill，辅助产出可审阅的技术规范书草稿。

查看 GitHub 项目 ↗

能力定位

把文档编写经验，变成可执行的方法。

面向 B 端招标技术规范书草拟场景，结合客户背景与产品功能清单，组织行业适配的章节框架和条款内容。重点是可重复的输入、确认、编写和检查机制，而非一次生成全文。

以下能力根据项目 README 整理；此页展示设计，不代表已独立验证运行效果。

SKILL CAPABILITY DESIGN

六个能力设计重点。

01

输入契约

采集客户名称与官网、行业、需求概要，优先获取产品功能清单；技术限制与交付时间作为补充上下文。

02

知识与清单驱动

客户背景调研与功能清单结构化解析共同驱动内容。缺少清单时标注推断功能，区分原始要求与建议补充。

03

阶段确认机制

先提交章节框架供用户确认，再逐章填充；每章确认后继续，支持局部调整与自定义框架。

04

输出深度约束

按章节定义概要、标准和详细深度，详细级展开至三级条款，关键参数用表格表达，避免章节深浅失衡。

05

可追溯标注

区分通用、行业定制、客户定制内容，标注需人工核实的参数与标准引用，将不确定性显式交给使用者。

06

校验与修订闭环

从结构完整性、条款一致性、标准引用、语气规范和标注五个维度检查；逐条修订并提供前后对比。

WORKFLOW

从输入到修订的完整路径。

  1. 信息采集
  2. 调研与清单解析
  3. 框架确认
  4. 逐章编写与确认
  5. 五维规范校验
  6. 反馈修订

输出规范

便于审阅，也便于后续交付。

输出 Markdown 草稿，以章节编号组织内容，标注草稿版本，并在附录集中汇总需人工核实的条款。可进入 Word 或文档协作工具继续编辑审核。

能力边界

把人工审核留在流程中。

Skill 辅助生成技术内容与引用建议；不替代最终法律、合规审核，不自动确定强制性参数，也不负责商务报价、合同或正式盖章文件。

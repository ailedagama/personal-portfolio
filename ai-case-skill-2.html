SKILL DESIGN / 数据结果解读

BI 数据洞察分析ChatBI Data Insight

面向智能问数结果，按数据结构选择解读模式，提炼关键数字、变化、分布与异常，形成克制的业务说明。

查看 GitHub 项目 ↗

能力定位

让业务更快读懂问数结果。

承接自然语言问数之后的表格、指标、排名和对比数据，为业务决策者生成简短、客观的中文解读。聚焦已有数据事实，不承担数据采集、SQL 生成、原因归因或趋势预测。

SKILL CAPABILITY DESIGN

把分析习惯，转化为可复用规则。

01

意图对齐

读取原始问题，明确核心指标、时间范围、业务范围与分析维度，避免脱离用户关注点。

02

数据结构路由

按单一指标、多行排名、对比表和汇总明细混合四种结构选择解读模式，而非套用同一段总结。

03

信息优先级

优先提炼 1–3 个核心数字，再组织显著变化、异常与结构分布；避免逐行复述表格。

04

异常提示规则

对极值、大幅同比环比变化及头部集中等信号主动提示。零值与空值需结合业务口径区分，固定阈值不代表统计显著性。

05

输出格式约束

以中文业务语言先总后分，通常 3–6 句话，复杂结果不超过 8 句；保留原始精度并突出关键数值。

06

推断与建议边界

禁止无依据归因、预测和引入外部假设。仅当数据信号明确且建议直接源于数据事实时，给出简短建议。

FOUR INTERPRETATION MODES

不同结果，采用不同解读策略。

A / 汇总指标

数值与已有对比

直接给出数值和单位，有对比时说明方向与幅度，无对比则只描述现状。

B / 多行排名

头部与结构

提炼 Top 1–3、显著差距和集中度，分布接近时避免夸大差异。

C / 对比表格

变化与例外

识别最大增减幅度、整体方向和逆势维度，保留可核查的数字事实。

D / 汇总与明细

先总后分

先说汇总，再补充关键明细和异常，避免将全部数据重复叙述。

WORKFLOW

从问题理解，到有边界的解读。

  1. 理解问数意图
  2. 扫描数据结构
  3. 选择解读模式
  4. 提炼事实与异常
  5. 组织简洁文本
  6. 检查推断边界

输入与输出

保留数据上下文。

输入包含原始问题、完整结果表和指标单位；输出围绕核心结论、变化分布、必要异常与可选建议组织自然段落，不机械输出模板标签。

设计价值

让结果解读更稳定。

以模式路由、事实优先级和语言约束组织模型行为，使输出更容易复核与复用。本案例展示 Skill 规则设计，不将规则本身等同于已验证的准确率或业务收益。
